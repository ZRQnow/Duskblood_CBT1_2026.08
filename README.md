# Duskblood-CBT1

《Duskblood》CBT1 测试期资料的私人归档仓库，用于集中保存原始图片、视频、访谈与招聘材料，并将来源、证据、分析、论点、草稿、质检和终稿分层管理。

> 本仓库默认包含未公开测试资料。提交、分享或引用前，请先确认保密协议、平台规则、版权与个人信息要求。

## 目录结构

```text
Duskblood-CBT1/
├── 00_brief/              # 项目简报、范围和读者约定
├── 01_sources_raw/        # 未改动的原始素材与来源记录
│   ├── official/          # 官网、预告、官方访谈、商店页
│   ├── gameplay/          # 原始试玩视频、音频和来源信息
│   ├── screenshots/       # 原始截图，按来源编号归档
│   ├── recruiting/        # 招聘页面、职位表和抓取记录
│   └── community/         # 社区、试玩者与媒体材料，仅作辅助证据
├── 02_evidence/           # 来源台账、帧测量、UI、规则和招聘信号
├── 03_analysis/           # 分主题分析文档
├── 04_narrative/          # 论点地图与成文提纲
├── 05_drafts/             # 工作草稿和修订版本
├── 06_qc/                 # 事实、引用、格式与发布前检查
└── 07_final/              # 通过质检的终稿和发布清单
```

## 快速开始

1. 先填写 `00_brief/brief.md`，确认研究目标、测试时间窗与交付物。
2. 将素材原样放入 `01_sources_raw/` 对应目录，不覆盖、不二次压制原文件。
3. 每加入一个来源，在 `02_evidence/source_register.csv` 登记来源编号、链接、获取日期和文件路径。
4. 只把可复核事实写入 `02_evidence/`；解释与推断写入 `03_analysis/`。
5. 在 `04_narrative/` 组织论点后，将草稿放入 `05_drafts/`。
6. 按 `06_qc/qc_checklist.md` 检查，通过后复制定稿到 `07_final/` 并更新发布清单。

## 统一编号与命名

来源编号使用 `SRC-类型-四位序号`：

| 类型 | 前缀 | 示例 |
| --- | --- | --- |
| 官方资料 | `OFF` | `SRC-OFF-0001` |
| 试玩视频 | `GMP` | `SRC-GMP-0001` |
| 截图 | `SS` | `SRC-SS-0001` |
| 招聘资料 | `REC` | `SRC-REC-0001` |
| 社区/媒体 | `COM` | `SRC-COM-0001` |

素材文件建议命名为：

```text
YYYYMMDD_来源编号_主题_序号.ext
```

示例：`20260821_SRC-OFF-0001_announcement-trailer_01.mp4`。

- 日期统一使用 `YYYY-MM-DD`；时间统一使用 ISO 8601，并注明时区。
- 文件名使用小写英文、数字、连字符或下划线，避免空格和特殊符号。
- 同一来源的衍生截图、帧测量和分析必须保留相同的 `source_id`。
- 不确定内容必须标为“待核实”或“推断”，不得写成已确认事实。

## 大文件与版本控制

仓库已通过 `.gitattributes` 将常见图片、视频、音频、设计源文件和压缩包交给 Git LFS 管理。首次克隆后执行：

```bash
git lfs install
git lfs pull
```

单个超大文件仍需遵守 GitHub 与账户套餐的存储限制。原始素材禁止用文本合并方式处理；发生冲突时保留两份并重新编号。

## 资料边界

- `01_sources_raw/` 只存原件与伴随元数据，不存裁剪、标注或分析后的版本。
- `02_evidence/` 只存可追溯、可复核的数据化事实。
- `03_analysis/` 可以包含解释，但必须引用来源编号并区分事实与推断。
- `07_final/` 只接收完成质检、注明版本与发布日期的文件。
- 不提交账号凭据、下载令牌、私聊原文、未脱敏个人信息或其他不必要的敏感数据。
